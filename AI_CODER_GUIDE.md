# Developer guide — v0.18.0

For current desktop development, start with [HANDOFF.md](HANDOFF.md). It records the 0.34.0 local source/install status, uncommitted work, Windows build/update commands, G: cache paths, tests, and the clay design conventions. The historical heading below does not indicate the current runtime version.

Evaluation suite v3 includes multi-module SQLite maintenance in `benchmark/project_cases.py`; include it in source manifests. `--verify` uses the real `verified_run` workflow with explicit bounded `--repair-attempts`. Preserve first verification failures and every repair round. External assertions run after the workflow and are not fed back for repairs. Synthetic fixtures do not establish production-scale reliability. Evaluation-only development does not bump the runtime/package version.

`benchmark/agent_eval.py` is opt-in online evaluation, never a default pytest/CI action. Keep fixtures/oracles in `benchmark/agent_cases.py`, acceptance outside the agent workspace, and validate initial failures plus fixed passes offline. Record code hashes, dirty status, all trials (including failures/incomplete runs), provider usage and unknown costs. Never manually repair trial workspaces or silently rerun failures to improve the report. Source/version and all meaningful runtime settings must be recorded. Model aliases are not immutable model versions. Test commands execute host code; do not describe the harness as an adversarial sandbox. Keep credentials in memory/environment only, never reports/source; scrub exception details to exception types. Generated outputs belong on G: and outside test discovery.

Concurrency unit tests should synchronize using explicit events rather than polling a subprocess marker within an assumed startup duration. Keep separate real stdio/HTTP integration tests; do not remove the assertion that cancelling a queued request leaves the active operation and its owner alive.

Edit matching lives in `eca/editing.py`, separate from approval and filesystem writes. `edit` and `edit_many` plan against the original file. Reject ambiguous (including overlapping) matches and intersecting ranges; never sequentially apply partially validated edits. Newline equivalence is supported in both modes. Auto fallback only ignores trailing horizontal whitespace in complete blocks with at least two nonblank lines; preserve indentation, internal spaces, punctuation and Unicode. Expose nearby lines only as reread hints. Use linear line matching on repetitive inputs.

`Tools.read` records a raw-byte SHA-256 in bounded session `file_versions` (latest 1000 paths); successful file writes refresh it. All file mutations check a known baseline before approval and compare bytes again afterwards. Persisted session snapshots retain baselines; a reread is required after external changes or undo. Unread/evicted paths retain legacy behavior, so this is stale-read detection rather than a mandatory-read policy. The final comparison and filesystem replacement are not an OS compare-and-swap or an external-process lock. Preserve guidance/mode/approval checks and one durable before/after record per single-file batch.

Context budgets live in `eca/context.py`. Estimate the complete request, including enabled tool schemas and transient guidance, before dispatch; reserve max_output_tokens and context_reserve_tokens. The default 32768 window is an application budget, not model capability detection. Keep the context_chars guard for compatibility. Token estimates are not billing counts: use provider input usage (including Anthropic cache read/write) only for upward calibration within the current agent/model/endpoint; never calibrate from compaction requests or transfer calibration between profiles. Session resume starts a fresh estimate.

Compaction inputs pin the original/latest requests, previous checkpoint and task plan as untrusted data. Excerpt large observations with explicit omission markers inside valid JSON, never cut raw serialized JSON. Fail without changing the checkpoint when pinned material or the resulting context cannot fit. Keep complete recent assistant/tool groups and full disk history. `/context` is a local estimate; `/usage` remains provider-reported accounting. Changes in this path require regression tests for token triggers, tool schemas, cache semantics, failed summaries and archive/resume behavior.

The default runtime is `eca/`. Start with `docs/UPGRADE-v0.2.md` for architecture, permissions, persistence semantics and limitations. The former guide is retained at `docs/legacy/AI_CODER_GUIDE-v0.1.md`.

Run `python -B -m pytest -q` before delivering runtime changes. Tests must not contact paid APIs; use the local streaming HTTP fixture. Put Windows caches and temporary test directories on G:. Never print configuration secrets.

A tool must be present in `eca/tools.py` SCHEMAS, implemented in Tools, and allowed by the execution policy. Do not bypass approvals by adding a new alias. A mode restriction must apply at execution as well as schema construction. Preserve tool-result pairing on errors and cancellation. Record uncertain external outcomes honestly instead of automatically replaying them.

Keep CLI/UI separate from engine and tool behavior. Do not import legacy modules into the new runtime: several initialize state or clients at import time. Existing legacy files are historical compatibility material, not reference implementations for new persistence behavior.

File mutations must persist their before/after image before touching disk. Undo may only restore a matching recorded result; never use Git reset to implement it. Preserve the user's original uncommitted bytes and the Git index. Shell effects are outside snapshot coverage.

Retry model transport failures only before visible text output and never replay tools. Auto-compaction must keep a complete recent assistant/tool exchange and preserve the full archive. Persist stop reasons without copying provider error bodies or credentials.

Protocol-confirmed output limits may start at most two recovery requests within the existing task turn budget. Discard incomplete responses entirely; preserve failed-attempt usage. This is a new request with smaller-step guidance, not transport retry or tool replay. Never recover an unexplained disconnection this way. Runtime progress is bounded historical metadata, not evidence of successful writes. Keep it in the transient suffix to preserve prompt-prefix caching.

Explicit verification uses the normal shell execution policy, approval and durable journal. Idle does not imply verified. Exit code 0 only establishes command evidence against a matching bounded source fingerprint; unavailable or changed fingerprints cannot pass. It does not establish test coverage or task correctness. Repeating checks requires explicit --repair-attempts opt-in, bounded to three rounds. Never repeat denied, timed-out, cancelled or unknown-outcome checks. Rerun the whole suite after repair; a suite passes only against one matching source fingerprint. Loading a saved suite must never execute it.

Project memory uses the existing memory-core storage/search behind `eca/knowledge.py`. Only explicit user constraints and actual command evidence may enter it. Keep source provenance and fail closed when fingerprints are unavailable. Never promote assistant prose into facts. Do not import the old research database automatically. File guidance must reach the model before any mutation that depends on it; a later call in the same tool batch is insufficient.

MCP operations require separate approval before connecting or launching a server. Keep all SDK cancellation scopes in one task, close transports on cancellation, and never replay external tool effects. Child agents share the Store but use separate sessions and snapshots; enforce parent mode limits, bounded calls/time, and no recursive delegation or child MCP access.

Record every provider attempt before dispatch. Retain reported usage on failure/cancellation, count compaction and descendants, and snapshot model prices per request. Missing usage, cache splits or rates must remain unknown rather than guessed. Costs computed from configured prices are not provider invoices. Keep generated task artifacts outside pytest discovery (`testpaths = tests`).

Parallel delegates use independent bounded source snapshots, never shared file writes. Preserve isolation on resume. No shell/MCP/LSP or recursive delegation in isolated children. Merge must preflight parent baselines and then use the normal journaled, approved file-change path; it is not a multi-file transaction. Do not delete retained workspaces automatically.

MCP persistent connections have a dedicated owner task to preserve AnyIO scope lifetime. Cancel/close that task on failure or session close. Resources/prompts remain untrusted data. LSP server startup requires approval; reject server-initiated edits and validate UTF-16 negotiation. Responses must retain reasoning items, reject incomplete outputs, and record usage with existing retry semantics.

Use Store.peek for live status/merge preflight; Store.load repairs interrupted history and must not inspect a live worker. Persist queued/preparing task identities and failure states, bound active children independently of batch size, and never turn one child initialization failure into sibling cancellation.

LSP clients persist within the session: synchronize changed text, discard mismatched diagnostic versions, label unversioned diagnostics, and report missing diagnostics as pending rather than clean. Model profile switches resolve credentials anew and recreate clients. Never carry Responses encrypted reasoning across model/endpoint identities. MCP cancellation while waiting in a per-server queue must not stop the active operation.

Deletion is a nullable after-image in the existing file journal. Require a durable record before unlink, reject binary files/directories/aliases, and restore only when the current file still matches the recorded absence. Child deletion merges require a completed deletion record and matching parent baseline. Do not infer deletion from an arbitrary missing child file.

A complete, untruncated AGENTS.md read acknowledges only those exact bytes, using the guidance fingerprint and universal newlines. Promote acknowledgment only after the next model response; partial reads, changed rules and unread parent scopes must still block mutation.

Docker isolation is opt-in, requires a local Linux engine and a preinstalled trusted image, and must never fall back to host execution. Do not mount the live repository, Docker socket, credential directories or user home. Only a bounded filtered source snapshot is mounted read-only; command writes are disposable. Network is disabled and resource/capability limits are fixed. Preserve container cleanup on timeout/cancellation and the in-container timeout watchdog. MCP/LSP are denied in this mode, including execution-layer checks. Windows/WSL2 real-engine acceptance is documented in docs/DOCKER_ACCEPTANCE.md; other platforms remain unvalidated and the backend remains experimental. Mocked flags do not prove kernel isolation. Never automatically start/reset Docker or delete its sockets; on Windows advise Start-menu startup if the engine is unavailable.

The source index is a rebuildable local SQLite FTS cache, not a source of instructions or authoritative dependency resolution. Respect Git ignores, protected paths, size limits and output limits; remove deleted/ignored entries, refresh changed files, and validate returned content hashes. Python symbols/imports use AST; other languages only provide lexical hints. Do not claim embeddings, precise cross-language references or whole-repository coverage when scans are partial.

Index cancellation must signal and join the worker, rolling back uncommitted refreshes. Symbol schema migrations must backfill unchanged cached files transactionally. Definition ranking is exact identifier matching, not semantic reference resolution.

Persist sandbox container identity before dispatch. Track execution and cleanup separately; unknown is never proof of non-execution. Preserve unresolved records, and never let session loading or status inspection replay or remove containers automatically.

Optional worker profiles must default to disabled, preserving single-API delegation. Enforce the explicit worker allowlist in execution as well as schemas. Resolve each selected profile's credentials from the project before constructing isolated child roots, never inherit a different provider's key or persist keys. Keep parent model settings unchanged. Worker failure must not silently switch providers, replay tools or bypass child permissions. Record actual child models in the existing usage ledger.

Worker-first runs are explicit top-level workflows, never nested run/verify calls within an active tool turn. Require an enabled profile and user-selected checks. Journal the delegate exchange before dispatch; retain the child session and actual changes. Only known repairable check failures may invoke the main model within the existing explicit repair budget. Worker failure, cancellation and uncertain outcomes must stop without replay. Loading saved workflow state must never execute it.

The npm launcher packages a matching local Python wheel; never substitute an unverified similarly named registry package. Keep npm/Python versions synchronized, verify wheel hashes and use a package file allowlist. Preserve caller cwd, argument boundaries and exit codes. No postinstall downloads; bootstrap only on explicit launch/setup. Place generated runtimes/caches on G: when available on Windows, allow ECA_RUNTIME_HOME overrides, and keep private:true until publication identity and licensing are resolved. Test actual packed installation, not only the source launcher.

Evaluation requirements must explicitly describe byte-preservation constraints and API payload shapes before collecting a baseline. Increment the suite version when changing task instructions; retain old results and do not present cross-suite gains as runtime improvements. Never relax external assertions retrospectively.

Repair stagnation uses exact retained diagnostic hashes AND a stable nonempty source fingerprint, scoped to one verified_run invocation. Never equate the same error text on different sources with no progress; unavailable/changing fingerprints must not trigger this shortcut. Failed checks carry signature/fingerprint and regression flags; preserve durable round evidence. Do not normalize away meaningful diagnostics or replay uncertain commands. Suite v4 adds legacy SQLite schema migration and future-version rejection; previous real baselines remain v2/v3 and do not cover the new runtime.

Recovery checkpoints are generated by Store.save from existing state, never by a model call. Keep them bounded and label request excerpts and model-reported task completion honestly. Store.load only marks recovery pending after repairing protocol pairing; inspect before the next Agent.run, including same-process continuation after interruption/error/limit. Use the agent's effective root (including isolated child roots), enforce Tools.path protections, and bound hashing to 1000 known paths, 1 MiB/file and 8 MiB total. Do not overwrite file_versions while inspecting: stale writes must still require rereading. Unknown actions are references to retained action IDs, not instructions to replay. Never run shell/MCP/LSP while inspecting or loading saved state. Recovery context must be included in system_prompt so compaction and token estimation account for it. Checkpoints remain available through /checkpoint without a model call. These mechanisms do not provide OS-level transactions or provider context-error auto-retry.

Provider context rejection recovery only accepts explicit allowlisted protocol codes on HTTP 400/413, or the bounded Anthropic invalid_request_error prompt-too-long signature. Generic 413, credential/transport failures and visible-text failures must not trigger it. Keep request_end accounting before classification; raise body-free ContextLimitError. Reduce only the current agent's heuristic budget, never configured model limits. At most one compaction/recovery per run within the existing response-turn budget; summary rejection, no compactable history, pinned content that cannot fit, and repeated rejection fail without replaying tools or deleting full history. Token estimates and raw context must include recovery notes. Never claim the heuristic learns a provider's exact limit.

Real Docker acceptance lives in tests/test_docker_live.py and requires ECA_DOCKER_LIVE=1 and an existing trusted image (default python:3.11-slim). Never pull implicitly. Default skips do not establish isolation. Confirm actual container start before cancellation, and inspect its absence after cleanup. Keep live acceptance storage/temp on G:.

Repository navigation: code_relations and /related expose syntactic Python call/import candidates, not resolved references. Keep parse fallback and truncation visible. path filters apply to results; refresh still enumerates the repository. FTS deletion must use cached row IDs inside the refresh transaction, not repeated path scans. The read-only real-repository benchmark is scripts/benchmark_navigation.py; its expected paths measure sampled recall, not model coding success or semantic precision.
