## 验证与修复运行时升级

- 每个已知失败记录诊断 SHA256、稳定源码指纹和 action_id，可回溯真实命令日志。
- 同一次工作流中，相同命令在相同源码上再次给出相同保留诊断时，停止继续修复，原因是 repeated_failure_same_source。源码或诊断改变时仍按原预算继续；指纹缺失或检查期间变化时不据此判停。
- 每轮标记之前通过、本轮失败的检查为 regression；CLI 展示停止原因和回归次数。修复后仍从第一项开始验证整组。
- 修复提示要求先定位失败要求和原因，再做有针对性的修改；提示本身不是约束强制执行，也不保证测试不被削弱。
- 增加 shop_migration：新旧数据库迁移、保留历史库存和订单、重复连接、拒绝未来版本、available API 与原购买行为兼容。

判停使用精确保留输出，不清理时间或临时路径，可能漏掉动态文本下的重复错误；仍受最多三轮预算约束。源码指纹有扫描边界，不包含全部外部状态，判停仅是成本控制，不是无法修复的证明。没有加入自动发现并执行未知检查；验证命令仍需用户指定。历史真实模型 9/9 不覆盖本轮新增运行时代码或迁移任务。

本轮最终验证：全量 **257 passed、2 skipped**；迁移任务 3 次完成实测均通过，另 1 次中断未完成。详细记录与限制见 [v0.19 验证记录](VALIDATION-v0.19.md)。本轮未重新打包或发布 npm。
