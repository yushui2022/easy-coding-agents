## 已验收范围

商品管理与乐观锁、库存调整、管理员/只读角色、严格数值验证、幂等下单、价格快照、失败回滚、
重复/并发取消返库、持久化重开、并发防超卖、分页与查询、审计去重、报表及 CSV 转义。
外部用例使用多个应用实例及线程池操作同一个 SQLite 文件。独立 HTTP 冒烟还启动了 Uvicorn，
验证健康接口、未认证拒绝、创建商品、下单金额和取消返库；该冒烟发生在最终测试/文档整理之前。

测试环境使用 Windows / Python 3.11.1、FastAPI 0.138.0、Pydantic 2.12.5、httpx 0.28.1、
pytest 8.4.2、uvicorn 0.49.0。测试中保留了依赖对 TestClient/httpx 的弃用提示，没有为消除提示而更换依赖。

## 真实过程：不是一次无人干预成功

1. 原 ECA v0.8.1 开始构建；完整读取 AGENTS.md 后仍重复阻断写入，且在压缩后再次出现。
2. 人工中断一次，保存同一会话；修复规则读取确认后续跑，业务文件保留。
3. 100000 字符预算下频繁压缩、重复通读源码，测试迟迟未完成。再次人工中断，预算改为 400000 字符，
   明确要求先补测试和基于失败做定点检查。此调整是验收配置，不是 ECA 的默认上下文修改。
4. 最后一次运行的前两阶段遭遇 RuntimeError；两次失败请求的输出用量均达到 16384 上限，未执行不完整工具调用。
   这两阶段核心业务均已通过 36 项外部测试，但自身测试为 0、交付文件不齐，不能判成功。
5. 运行器反馈失败后，第三阶段补齐自身测试和文档，最终所有检查通过。完整会话共保存 33 次文件工具变更。

另外出现一次 Shell timeout 使用错误单位的调用，工具拒绝后模型改用秒数，后续执行成功。
上述失败、人工指引及配置调整都不能从报告中抹掉，也不能将结果称为原版本独立一次性成功。
