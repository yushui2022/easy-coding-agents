# 大仓库定位与增量索引

模型可调用 `code_relations(query="symbol", path="backend", limit=20)`，或在终端输入 `/related symbol`，获取定义、Python 调用和 `from ... import ...` 位置。测试文件会有 `is_test` 提示。`code_search` 与 `repo_map` 同样支持可选 `path`，按相对文件/目录边界筛选结果，不把 `src` 当成 `src2`，也不解释通配符。

这是语法候选查询，不是语义调用图：同名方法可能无关，别名、动态调用和间接测试可能漏掉。改代码前仍需读取候选文件；需要精确解析时使用配置好的 LSP。Python AST 不支持当前源码语法时，保留词法定义并返回 `parse_status=syntax_error`；其他语言只提供词法定义/文本定位。

每次查询重新枚举和 stat 文件；未变化文件复用缓存，只重新读取/解析变化文件，并在返回结果前读取并核对摘要。目录筛选只限制结果，不缩小索引刷新范围。删除、重命名、忽略规则变化和分支切换会清掉不再可用的旧记录。首次升级将重建旧格式缓存。取消刷新会回滚事务，不发布半次更新。

输出统计包括 `updated`、`reused`、`removed`、`files_read`、`bytes_read`、`elapsed_ms` 和 `syntax_fallback_files`。读取统计包含索引刷新和结果摘要复核，不包含 Git 自身的文件操作。复用缓存不意味着跳过目录枚举，因此热查询仍可能受文件系统速度影响。

索引限额仍为每文件 1 MB、总计 100 MB；每文件最多 100 个定义、100 个导入摘要、1,000 个调用/导入位置。关系结果每文件展示最多 20 个位置并标记截断。所有结果还受条数和输出长度限制，不能把空结果解释为“绝对没有调用者”。不执行仓库源码，不启动语言服务器，不调用模型 API。

## 复现实仓库定位测量

固定任务清单为 `benchmark/repository-navigation.json`。使用匹配 revision 的本地 DeerFlow 仓库：

```powershell
python -B scripts/benchmark_navigation.py --root G:\Projects\deer-flow --output G:\DevCache\Temp\easy-coding-agents\navigation
```

索引数据库和报告只写入指定输出目录，要求它位于被测仓库之外。报告包含仓库版本、任务清单摘要、首次建索引和后续查询统计、预先指定文件的命中率。只读 Git 状态在测量前后对比。

这三项是定位验收，预期文件并非穷尽列表；不测完整语义准确率，也不等于真实模型跨文件修改成功率。真实模型修改、项目测试通过率和其他语言定位仍需单独验收。
