# v0.12：定义优先检索、可取消索引与容器审计记录

## 这次改了什么

- `code_search` / `repo_map` 及 `/search` / `/map`：单个标识符优先匹配大小写一致的符号定义，返回 `matched_symbols` 和行号，再补充全文搜索结果。SQLite 符号表按名称建索引，旧缓存事务内迁移，未修改文件也会补齐。
- 取消索引会通知工作线程，在文件处理边界停止，回滚未提交更新，并等待线程退出，避免后台继续写数据库。已经完成并提交的刷新可以保留。当前文件解析、系统 I/O 和 Git 枚举不能即时抢占；Git 枚举有 10 秒超时。
- Docker 调用前保存唯一容器名、本地 endpoint、镜像和创建时间。执行结论与清理结论分别保存，写入失败则不派发容器命令。正常、失败和取消路径都尝试清理并保存结论。
- `/sandbox` 只查看当前会话记录，不连接 Docker、不启动引擎、不重放命令。保留最近 20 次已清理运行以及全部未确认记录；未确认记录达到 100 条则阻止新执行。

## 如何理解容器状态

`execution=finished` 只表示获得命令退出结果，必须同时检查 `exit_code`；不表示业务成功。`unknown` 表示没有确定执行结果，不能推断没有发生副作用。

`cleanup=pending` 表示尚无持久清理结论（例如进程突然退出），`unconfirmed` 表示清理未确认，`removed` 表示删除或容器已不存在得到确认。恢复后由使用者按记录的 endpoint 和名称检查容器；本版不自动清理历史容器，也不提供修改历史结论的命令。

## 仍然存在的边界

这不是跨语言语义索引：Python 用 AST，其他语言仅词法摘要，每文件最多 100 个符号；索引仍需遍历元数据，并受原有容量限制。容器记录改善可追踪性，不提供宿主机进程硬崩溃后的自动清理保证。

Docker 后端仍是实验功能：本机 Linux Docker 引擎不可用，真实容器隔离验收未运行；模拟参数和生命周期测试不证明内核隔离有效。不得把本次升级描述为已经达到企业级安全验收。
