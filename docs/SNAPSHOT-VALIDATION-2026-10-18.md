# 大仓库源码指纹升级与复验

此前 DeerFlow 的跨文件修改和七项行为测试通过，但源码指纹因单文件 2 MB / 合计 50 MB 上限不可用，验证工作流正确地拒绝标记成功。本次针对这一阻碍升级。

## 实现

- 使用 1 MiB 分块计算全部纳入文件的 SHA256，不忽略大文件，也不使用修改时间缓存替代内容读取。
- 默认上限为 20,000 个文件、512 MiB 总内容、30 秒。超限、读失败或发现并发变化时返回未知，仍不得确认测试证据。
- 读取前检查路径元数据和打开的文件句柄；读取后检查长度和元数据；最后重新枚举文件清单并核对所有文件，覆盖读取过程中新增、删除、重命名及先前文件变化。
- Windows 按路径获取 `.cmd` 等文件状态时会合成执行位，而文件句柄状态不会；比较时只对 Windows 忽略这些执行位，保留标识、类型、读写权限、大小与时间检查。
- 非 Git 目录自行完整枚举并执行扫描预算，不复用可能提前截断的导航文件迭代器。现有秘密路径、工作区边界与排除目录政策保留。
- 指纹格式升级为 v2，旧验证记录可能显示 stale，需要重新验证。历史记录不被篡改。

这不是操作系统级原子快照，也不防御有意恢复所有元数据的对手。每次仍需读取全部纳入内容；不把更大容量宣传为更快。
