# 长任务检查点与恢复

恢复升级已包含在 0.19.0 npm 安装包中；旧安装包需要升级后才能获得这些改动。

## 使用

```text
ecs --resume latest
/checkpoint
/continue
```

`/checkpoint` 本地显示保存的需求摘录、任务状态、近期操作和最近一次恢复检查，不调用模型。`/resume` 加载历史；直到下一次运行或 `/continue`，才进行有界文件核对并把结果交给模型。初始化加载后、同进程发生中断/错误/轮次耗尽后继续，均会核对。

检查点随会话保存，不依赖模型摘要。原始消息和操作日志仍为完整来源，需求摘录有长度限制；任务的 completed 状态是模型报告，不等于已通过验收。记录中的 verification_action 对应原操作日志。

## 恢复前检查

- 对会话曾读写并保留版本的文件比较 SHA256，区分 matching、changed、missing、unverified；最多 1000 路径、单文件 1 MiB、累计读取 8 MiB。摘要最多展示 20 个异常路径，计数保留全部已记录路径。
- 受保护路径、越界、读取失败、超出预算均记为未核实，不当作没有变化。使用子 Agent 实际工作目录。
- 不更新旧文件版本基线。外部修改仍会触发原有陈旧读取保护，模型需重新读取后才能编辑。
- 根据已有源码指纹判断验证是否过期；报告状态而不自动重跑检查。
- 显示日志中 running/interrupted 操作 ID，要求先检查真实效果，不推测成功或失败，不自动重放工具。
- 需求与任务的有界摘录一并进入恢复上下文，按同样的 token 预算处理。

## 边界

这不是完整仓库快照。未读文件、已淘汰版本、超限文件和外部系统状态不能由匹配哈希证明安全。检查后文件仍可能被其他进程改变；现有编辑时的检查继续有效。恢复报告带时间，是历史观察，不是持续监控。

未知操作提示不等于强制阻止模型以后请求同一命令，后续工具仍遵循原权限策略。没有增加跨文件事务、外部效果回滚或操作系统沙箱。只保存状态和提供证据，不保证任何任务自动完成。

本地上下文预检失败会保留检查点；用户缩短输入、压缩历史或调整预算后可继续。后续新增了明确供应商超限拒绝的一次自动恢复，见 [上下文超限恢复](CONTEXT_RECOVERY.md)；未知网络错误仍不据此重放。

## 回归覆盖

专项覆盖外部文件变化/删除、受保护及过大文件、验证失效、超时后继续、上下文预算纠正后继续，以及实际子进程执行效果后 os._exit 的恢复。后者检查效果保留、未知工具结果配对和恢复检查未执行任何工具。没有使用真实模型 API。

早期验证结果：专项 37 passed、1 skipped；随后全量 **261 passed、2 skipped**（168.46 秒）。两组有重叠。上述验证没有调用真实模型 API；后续已提交并纳入 0.19.0 安装包。
