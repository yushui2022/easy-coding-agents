# 供应商上下文超限恢复

服务商明确拒绝请求大小时，运行时可在原响应轮次预算内恢复一次，不必先丢弃会话。

## 触发条件

- HTTP 400/413 且结构化 code 是 context_length_exceeded、context_window_exceeded 或 input_too_long。OpenAI 兼容 Chat/Responses 共用此路径。
- Anthropic HTTP 400、invalid_request_error 且 message 以 prompt is too long 开头。最多读取 64 KiB 错误体，异常消息不携带原文。
- 普通 413、鉴权错误、网络失败、模糊报错或已经向用户输出文本的请求，不转换为这种恢复。

## 执行方式

失败请求先入用量账本。将当前 Agent 的估计预算收紧到不超过被拒请求的一半，再调用现有摘要机制，保留原始/最新请求、旧摘要、任务与最近完整消息组。预算只是保守估计，不是服务商的真实窗口探测；不会修改配置或切换模型。

摘要成功且历史截点前进后，下一响应轮次继续。每次 run 最多一次该类恢复。没有足够轮次、没有可压缩历史、固定内容装不下、摘要也遭拒绝或再次遭拒绝时停止并保留会话。旧摘要只有在新摘要校验通过后才替换，已执行工具不会由该机制重放。

不覆盖所有服务商错误文案，也不把流式 response.failed 模糊错误当作可恢复拒绝。供应商未提供用量时保持未知，不记为零费用。

验证：上下文/恢复专项 18 passed；最终全量 266 passed、5 skipped。使用本地协议模拟和确定性 Provider，无真实模型调用。本轮尚未重新打包。
