# ECS 0.20.0 DeepSeek 真实编码验收

结论：在本轮有明确需求与自动验收的 Python 维护任务中，ECS 已体现实用性。
证据不足以宣称企业级成熟、任意仓库可靠，或无人监督交付复杂项目。

## 结果

| 方案 | 严格通过 | 模型请求 | 任务耗时合计 | 单任务中位数 |
|---|---:|---:|---:|---:|
| Flash：14 类任务各两遍 | 26/28 | 242 | 660.46 秒 | 21.88 秒 |
| Pro：3 类配对任务各两遍 | 6/6 | 44 | 282.37 秒 | 49.78 秒 |
| Flash-first，Pro 备用：相同配对任务 | 6/6 | 33 | 110.85 秒 | 18.45 秒 |
| Flash：DeerFlow 真实仓库快照 | 1/1 | 13 | 111.19 秒 | — |

共 41 个任务实例、332 次模型请求。各组部分并发，耗时合计不能视为墙钟时间。
没有人工修补任务文件；所有结果保留原始失败记录。

固定任务覆盖基础修复、重构、补测试、并行合并、中断恢复、跨模块接口迁移、
用户修改保留、工具读取失败、上下文压缩、配置解析，以及 SQLite 迁移、
订单幂等、取消与批量操作。每项最多 24 轮、480 秒、48 次共享请求，允许一次
验证失败后的主模型修复。40 次固定任务的运行时验证均首轮通过，没有触发修复。

## 两个严格失败的含义

`compact-01` 和 `config-02` 的业务断言和 unittest 均通过，但在已有测试文件中
追加测试，导致 `original_tests_preserved` 的字节相等检查失败。
检查 diff 后未发现删除或弱化原断言。它们仍保留为严格失败，不能事后修改评分。

评测提示只写“Preserve existing tests”，而判定要求文件完全不变，存在歧义。
后续应分别衡量“原测试语义保留”和“文件完全不变”，或提前明确禁止编辑测试文件。
本次不将它们解释为两次功能错误，也不将严格成绩重写成 28/28。

数据库迁移第二次最终成功，但用了 18 轮、约 79 秒；显示成功任务的搜索、补测
和收敛成本仍会波动。日常使用应保留检查点、预算和人工 review。

## 多模型结论

配对任务为 api、shop_idempotency、shop_cancel，各两次，使用相同外部验收。
Flash-first 本次较 Pro 单模型耗时减少约 61%、请求减少 25%。这是六个实例的
观察结果，不是普遍性能保证，供应商延迟和顺序执行均会影响对比。

所有 Worker 均独立完成，Pro 没有接手；因此本次证明的是轻量模型能完成这些任务，
没有证明失败升级策略能提升成功率。两组均 6/6，也不能声称协作提高了成功率。

## 大仓库边界

DeerFlow 固定 revision `34316550dffbe8fbaed5678a6be87c5d3c65155b`，4012 文件，
按评测既有记录排除两个文件。使用隔离 Git 快照，原仓库状态保持不变。
跨七个允许文件迁移公开异步 helper，并验证消息绑定分支行为。
外部七项契约及所有范围、语义、暂存区和源码状态检查均通过。

此任务显式使用 600000 字符上下文、262144 token 配置和 120000 字符工具输出，
不是默认配置。只验证一个定向维护任务；绕过部分包初始化并 mock 存储边界，
没有运行上游完整测试，也没有验证生产部署、浏览器或真实多语言 LSP。
