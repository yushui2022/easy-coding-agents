# v0.8.1：可恢复的文件删除

编码任务现在可以通过 `delete(path)` 删除过时的源码文件，不必调用无法通过文件快照撤销的 Shell 命令。

- 仅 code 模式可用；支持单个不超过 2 MB 的 UTF-8 文本文件，拒绝目录、二进制内容、受保护路径和路径别名。
- 默认展示删除差异并确认，`--accept-edits` 同时授权创建、编辑和删除。空文件也显示明确的删除提示。
- 删除前保存原始字节和“文件不存在”的结果状态；删除后可使用 `/changes ID`、`/accept ID`、`/undo ID`。
- 审批期间文件被修改时拒绝删除。删除后用户重新创建文件时，撤销拒绝覆盖。
- 数据库写入失败时不删除；删除失败留下 prepared 记录，可通过 `/undo ID` 检查和恢复，不自动重试删除。
- 隔离子 Agent 的结果清单标记 `deleted`；`merge_agent` 只合并有已完成删除记录的文件，并检查父目录是否仍与源码快照一致。

例如：让 Agent 删除已确认无引用的旧模块，查看 `/changes`，需要恢复时执行 `/undo ID`。涉及多个修改时，应按 ID 从新到旧撤销。

## 边界

文件快照保留内容，不保留权限或时间戳。文件系统检查与实际修改之间仍存在系统级竞争窗口，不能替代操作系统沙箱。多文件合并仍逐项审批和落盘，不是原子事务；后续文件被拒绝时，前面的修改可能已经生效。Shell 删除不在此功能的撤销范围内。

本轮未改变 MCP、LSP、模型接入的能力范围，未新增 OAuth、操作系统沙箱或自动三方合并。
