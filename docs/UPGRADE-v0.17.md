# v0.17：可靠编辑与单文件批量修改

## 使用

继续通过 `ecs` 给出编码需求即可，模型可使用原有 `edit` 或新增 `edit_many`。不需要配置额外 API。

`edit_many` 示例工具参数：

```json
{
  "path": "src/config.py",
  "edits": [
    {"old": "TIMEOUT = 10", "new": "TIMEOUT = 30"},
    {"old": "RETRIES = 1", "new": "RETRIES = 2"}
  ],
  "match_mode": "auto"
}
```

所有 `old` 都在原文件中定位，而不是前一个替换的结果。范围必须各自唯一且互不重叠；1～100 处修改全部通过后才展示合并差异、按原权限策略申请批准、写入一次，生成一条修改记录。`/undo ID` 恢复整次修改前的原始字节。任何一处匹配失败都不写文件、不生成应用记录。

## 匹配规则

1. 首先按换行等价的精确文本匹配。LF、CRLF 与 CR 输入兼容；重复匹配（包括相互重叠的匹配）拒绝执行。
2. 精确匹配为零且 `match_mode=auto` 时，才尝试完整多行片段的行尾空格/制表符差异；至少包含两条非空行，结果仍须唯一。
3. 不忽略缩进、不压缩内部空格、不删除空行、不改变引号/标点或 Unicode；单行编辑不启用行尾容错。`match_mode=exact` 可关闭此容错，但保留换行兼容。
4. 未修改区域保持原字节（包括 BOM、中文和混合换行）。替换文本采用文件既有的 CRLF 优先、其次 CR、否则 LF 风格。混合换行文件的替换区域会统一到该风格。
5. 失败输出包含原因、最多五个候选/相关位置的有限上下文。这些信息用于重读，不会自动选择某个候选。

行尾空白在某些文本格式中也可能有语义；此匹配是受约束的文本规则，不是语言语义证明。需要严格匹配时使用 exact，并检查正常生成的差异。

## 文件变更检测

读取文件时记录完整原始字节摘要（部分行读取也记录该版本）；成功保存后更新摘要。之后的 edit、edit_many、write、delete 检测到文件与该摘要不同时，要求重读，拒绝覆盖。审批等待期间仍会再次比较原始字节。

摘要随会话保存，恢复会话继续生效；最多保留最近 1000 个路径。没有读取记录或记录已淘汰的文件保留旧版行为，不强制首次编辑前读取。撤销或 Shell/其他 Agent 修改后可能需要重读。摘要不证明模型已理解全部内容。

本版不提供跨进程文件锁或 OS 级 compare-and-swap，最后一次核对与替换之间仍存在外部写入竞态。单文件批量写入沿用原有临时文件替换机制，不是跨文件事务。
