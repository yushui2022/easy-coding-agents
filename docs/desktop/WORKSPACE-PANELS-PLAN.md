# ECA Desktop 右侧工作区调研与升级方案

日期：2026-10-19。基线：0.25.1。状态：调研与实施设计；0.26.0 已据此实现首轮功能，实际范围与验收状态见 [0.26.0 记录](VERIFICATION-0.26.0.md)。

## 1. 用户目标

用户明确要求 Codex 那种**右侧独立的侧边聊天**，同时支持浏览器和终端。中间的主对话继续执行任务；用户可以在旁边解释报错、询问进展、查看网页、运行项目，再把需要落实的结论交给主对话。

右侧从固定宽度的“任务详情”升级为可调整宽度、可切换内容的工作区。现有修改、验证、进度与用量继续保留。沿用 Electron / React / TypeScript 与 Python 核心，不引入另一套 Agent 框架。

## 4. 布局与入口

```text
┌──────────────┬─────────────────────────┬─────────────────────────────┐
│ 项目 / 会话   │ 主任务 · 正在运行         │ 侧边聊天 ×  浏览器  终端  ＋ │
│              │                         ├─────────────────────────────┤
│ 当前项目      │ 对话、工具记录、授权       │ 来源：当前任务 / 选中的内容   │
│ 历史会话      │                         │                             │
│              │                         │ 解释报错、讨论方案            │
│              │                         │                             │
│              │                         │ [放入主对话草稿]             │
│              ├─────────────────────────┼─────────────────────────────┤
│ 设置         │ 主任务输入 / 停止主任务    │ 侧聊输入 / 停止侧聊           │
└──────────────┴─────────────────────────┴─────────────────────────────┘
                         可拖动分隔条 ↑
```

- 主对话标题栏提供“侧边聊天”“打开工作区”入口；选中文本可“在侧边聊天中询问”。
- 右侧上方是已打开内容的标签栏；“＋”菜单包含侧边聊天、浏览器、终端、审查。允许多个浏览器及终端标签，首轮每个主会话只允许一个侧聊同时生成。
- 首次打开侧聊默认约占可用内容区的 45%，打开浏览器约占 55%；拖动后记住用户比例。聊天与浏览器的最小可用宽度由布局测试确定，不继续固定为 310px。
- 可全宽显示当前标签，也可收起工作区。窄窗口在“主对话 / 工作区”之间切换，保留主任务状态和待授权提示；不挤成四列。
- “审查”承接修改与验证；任务进度、用量放在任务信息中按需展开。差异可在工作区展开阅读。
- 没有内容时只显示“打开侧聊 / 预览页面 / 新建终端”，不默认展示大片“未验证”。
- 标签切换保留输入、滚动位置和运行状态；收起面板不会取消工作。关闭浏览器标签销毁页面；关闭运行中的终端或侧聊有明确停止语义。
- 快捷键按焦点作用域处理：Ctrl+Alt+S 侧聊、Ctrl+T 浏览器、Ctrl+反引号终端、Ctrl+Shift+B 切换工作区布局。终端聚焦时 Ctrl+C 给终端，浏览器聚焦时 Ctrl+R 刷新页面，不重载整个应用。

## 5. 侧边聊天

### 上下文与实际用途

例如主任务在生成 3D 场景时，右侧可问“为什么截图读取失败”“刚才那个命令会做什么”“现在有哪些文件已经完成”。

新建侧聊时记录主会话 ID、来源消息 ID、上下文版本和时间，继承当前任务目标、已完成步骤摘要及用户选中的内容。界面显示“基于哪一刻的上下文”，支持主动刷新。不要每轮复制整个长历史，也不要转入未完成的 tool-call / tool-result 对。

侧聊记录独立保存在原项目 Store 中，用 `kind=side_chat` 与 `parent_id` 关联，不挤入主对话的消息序列或普通会话列表。关闭标签不删除历史；重新打开可恢复，崩溃后的未完成请求标为中断，不能自动重发。旧 CLI 加载普通会话不受新增字段影响。

### 执行、取消与模型

- 默认沿用打开侧聊时主会话选中的模型；侧聊可单独选择已有连接，不改变主任务模型。
- 主任务运行期间侧聊可以请求模型，具有独立 run ID、消息流与取消按钮。主任务的“停止”只停主任务及其委派工作，侧聊的“停止”只停侧聊；应用退出清理全部所属运行。
- 首轮侧聊支持问答、项目内读取与搜索。权限在工具调度层按白名单执行；不把 `plan` 模式整体当成绝对无副作用保证，不开放 shell、文件写入、重命名应用、MCP 和递归委派。
- 读取文件时记录版本/时间；主任务仍可能继续写同一文件。回答引用的是读取时的内容，不能宣称是冻结仓库快照。
- “放入主对话草稿”带来源引用，由用户发送；主任务忙时也可先保存这段草稿，首轮不暗中插入执行，也不重启主任务。
- 主 Agent 与侧聊共用计费根与原子请求预留，显示“主任务 / 子任务 / 侧聊 / 总计”。费用缺定价仍为未知；不能把同一侧聊费用重复计入父子汇总。

如以后需要侧聊直接承担独立编码任务，应转为独立 worktree 或由主运行时串行接管，这是下一层能力。当前项目锁继续由一个后端持有，不创建第二个 Store 抢同一个锁。

## 6. 浏览器

首轮提供地址栏、前进/后退、刷新、加载/失败状态、复制地址、系统浏览器打开，以及 HTTP(S) 与本地项目预览。终端发现 localhost 地址时显示可点击链接；服务未就绪时显示连接错误与重试，不把日志里的“Ready”当验收通过。

技术上采用主进程拥有的 `WebContentsView`，由应用布局传递经过校验的可见区域。网页独立渲染，不向网页暴露 ECA preload、模型连接或 RPC。开启沙箱与上下文隔离、关闭 Node；导航、弹窗、下载和权限由所属浏览器会话管理。[Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view) · [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

- 浏览器按项目绑定，使用与应用页面隔离的 partition；缓存和本机下载默认在 G 盘配置目录下，清除缓存不得删除模型密钥或项目数据。
- 本地 HTML 通过仅映射当前项目允许目录的预览协议加载；解析后的真实路径不得通过 `..`、符号链接或重解析点越界。验证 ES modules、相对资源、fetch 与 MIME。需要开发服务器的项目优先使用已有 localhost 地址。
- 不关闭 webSecurity 来解决页面兼容问题。设置、授权或退出弹窗打开时临时隐藏原生浏览器视图，避免覆盖弹窗或截获点击；多 DPI、缩放和窗口 resize 必须测。
- 页面文字、浏览器错误、选中文本可作为明确标注来源的附件送入聊天。截图能否送给模型还取决于核心及模型的图像能力；不能把图片路径发给文本读取工具后称为视觉验证。
- 这一步交付用户可操作的浏览器。Agent 自动点击、截图理解与网页验收需要另接浏览器工具、权限与模型能力检查，不因加入预览窗口就自动获得。

## 7. 终端

采用 xterm.js 渲染，专用 PTY 服务承载 node-pty，Windows 使用 ConPTY。默认 PowerShell、工作目录为当前项目；支持中文输入、方向键、Tab、ANSI、复制粘贴、Ctrl+C、resize 与多终端。[node-pty 官方项目](https://github.com/microsoft/node-pty)

- PTY 服务用独立进程隔离原生模块异常，由 Electron 主进程监管；API 密钥不注入终端环境。保留 PowerShell 所需的 PATH、SystemRoot、TEMP 等环境，本机临时目录指向 G 盘。
- 用户终端和 Agent 的 `shell` / `process_start` 分清所有者。已有后台任务可以显示日志、停止与地址，但不能假装已接入可输入 PTY。首轮 Agent 需要运行命令仍走现有 Python 授权链路。
- 提供“将选中输出放入聊天”，附带 terminal ID、工作目录、采集时间与截断标记。原始输出不会每次无条件塞进模型上下文。
- 不凭通用 PowerShell 屏幕文字推断可靠退出码。正式验证仍使用现有结构化检查记录，避免用户终端输出被误标为通过。
- 终端数据采用批量消息和高低水位流控，直接写 xterm，不经 React 全局状态逐字符刷新。隐藏标签保留有界缓冲，超出部分明确标记；不因为显示缓冲限制停止主模型任务。[xterm 流控说明](https://xtermjs.org/docs/guides/flowcontrol/)
- 关闭终端结束该终端所属进程；收起面板继续运行。用户手动终端不会被“停止主任务”误杀。退出应用清理所有所属 PTY 与子进程，超时提供明确状态，不按进程名批量杀进程。
- node-pty 属于原生依赖，必须为实际 Electron 版本验证 ABI、打包路径与运行库。构建机可需要 C++ 工具链，用户安装包不应在首次启动时编译。[Electron 原生模块说明](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)

## 8. 模块与接口调整

建议新增模块，避免继续扩充单体 `index.tsx`：

| 文件 / 模块 | 职责 |
| --- | --- |
| `desktop/src/renderer/workspace/Workspace.tsx`、`workspace-state.ts` | 标签、分隔条、全宽/分屏、持久化布局、焦点与快捷键 |
| `desktop/src/renderer/workspace/SideChat.tsx` | 侧聊记录、上下文来源、模型选择、独立输入与停止 |
| `desktop/src/renderer/workspace/BrowserPanel.tsx` | 地址栏、页面状态、浏览器视图的布局占位 |
| `desktop/src/renderer/workspace/TerminalPanel.tsx` | xterm 挂载、输入、大小、流控和日志引用 |
| `desktop/src/renderer/workspace/ReviewPanel.tsx` | 迁移现有差异与验证，保留撤销一致性检查 |
| `desktop/src/main/workspace.ts`、`browser-manager.ts` | 活动项目、标签所有权、WebContentsView 与预览资源 |
| `desktop/src/main/terminal-manager.ts`、`terminal-host.ts` | PTY 专用进程、会话注册、流控与清理 |
| `desktop/src/preload/index.ts`、共享类型 | 限定的方法、参数、事件订阅；不暴露 raw ipc 或任意 JS 执行 |
| `eca/side_chat.py`、`eca/runtime.py`、`eca/desktop_rpc.py` | 同一项目所有者内的独立侧聊、上下文快照、取消与事件路由 |
| `eca/store.py`、`eca/budget.py`、`eca/usage.py` | 分支保存、兼容读取、共享预算与去重汇总 |

通信设计：

- 握手增加能力声明，前端遇到旧后端禁用不支持的入口；若改变既有消息含义才升级协议版本。
- 侧聊使用独立 `sidechat.create/send/cancel/snapshot/context` 接口；事件带 project/session/branch/run ID，拒绝过期分支或错会话回复。主任务的 `task.*` 行为保持原样。
- 浏览器、终端使用主进程限定 IPC，分别以 tab ID、terminal ID 绑定当前项目与会话；不允许 renderer 提供任意外部 PID 进行终止。
- 快照恢复布局、侧聊和所属进程状态，不能在 UI reload 时重新发送模型请求、启动命令、提交授权或重新创建重复 PTY。
- 侧聊 Agent 的 close 只关闭自身资源，项目 Store 最后由项目所有者统一关闭。现有 `Runtime.close()` 会关闭 Store，不能不加区分地复用它关闭侧聊。

## 9. 执行顺序

1. **工作区结构与兼容基础**：先抽取现有审查面板，建立标签、布局、焦点与所属会话状态；同时验证当前 Electron 的 WebContentsView 和 node-pty 打包可行性，尽早暴露原生依赖问题。
2. **右侧聊天完整链路**：接入上下文、独立请求/取消、只读工具白名单、共享计费、恢复及“放入主对话草稿”。优先完成用户明确指定的核心交互。
3. **浏览器与项目预览**：真实页面加载、localhost、项目 HTML、错误恢复、切换标签与原生视图遮挡处理。
4. **真实终端与关联操作**：PTY、流控、进程树清理、日志引用、localhost 链接；保留既有 Agent 执行审计。
5. **联合验收与安装包**：在长主任务、侧聊生成、浏览器页面和终端持续输出同时存在的情况下测响应，再跑实际安装后的完整流程。

完成各阶段前不提升文档中的“已支持”范围。版本号在确定实际交付范围后统一更新，不为调研预先宣称新版本已完成。

## 10. 验证与验收

| 场景 | 验收标准 |
| --- | --- |
| 主任务修改文件时询问侧聊 | 主任务不中断，回答关联正确上下文；侧聊不能写文件、执行 shell、借 MCP 或 LSP 绕过限制 |
| 取消、授权、模型错误与额度耗尽 | 主/侧 run 不串线；重复或过期回复被拒；总请求次数预留原子化、用量不重计 |
| 旧 CLI/桌面会话、项目锁 | 读取和恢复兼容；不启动第二个项目写入所有者；外部文件变化仍拒绝覆盖 |
| 切标签、调整宽度、中文输入、刷新 | 草稿、焦点、滚动与内容保留；不重复发任务或启动命令；窄窗口可用 |
| 本地 HTML 与开发服务器 | 相对资源和模块加载正确；未启动、断连及端口变化可识别；预览路径越界被拒 |
| 页面与应用边界 | 网页不能访问 ECA IPC/连接密钥；重定向、弹窗与下载按既定规则；原生页面不覆盖授权弹窗 |
| PTY 实际操作 | PowerShell 中文、交互输入、Ctrl+C、resize、退出码来源说明正确；终止仅针对所属进程 |
| 隐藏/关闭/切项目/退出/崩溃 | 隐藏不等于停止；切项目处理所属运行后再切换；不自动重放，不遗留已确认退出的所属服务 |
| 打包与安装 | 未预装 Node/Python 环境能运行浏览器及终端；中文、空格路径和普通用户可用；升级保留模型与会话 |

性能目标属于待测门槛：联合负载下输入与标签切换反馈 P95 < 100ms，停止点击视觉反馈 < 100ms；本地可取消模拟请求的清理完成 < 2s。分别记录前端反馈、后端取消和进程退出时间，不以模型返回速度替代界面响应。与 0.25.1 同机、同测试口径比较，记录额外内存、冷启动、安装体积、浏览器关闭后的资源回收和持续输出时的长任务。

模型测试使用本地模拟服务覆盖成功、慢流、断连和取消；终端与浏览器用真实 Electron / PowerShell / localhost。新增测试建议为 `workspace.test.cjs`、`workspace-e2e.cjs`、`terminal-e2e.cjs` 与 `test_side_chat.py`，再执行 Python、npm CLI 和桌面原有回归。缺少独立干净 Windows 环境时明确列为尚未验收。

## 11. 真实风险与范围

- 浏览器页面、主模型流、侧聊流和终端持续输出会同时增加负载；按需创建资源，独立事件通道，避免每次 token 或终端输出都重新请求完整会话快照。
- 原生视图的层叠与多 DPI 坐标、PTY 的 Electron ABI 和 Windows 子进程清理，是实现和打包的主要技术风险，需在早期验证。
- 侧聊拥有上下文不等于拥有冻结文件；旧结论返回主任务时需重新核对实际代码。
- 现有 shared_request_limit 是请求次数预算，不能宣传为严格金额封顶；真正金额封顶还需要已知定价、预留和结算策略。
- 内置浏览器不自动赋予模型视觉或电脑操作能力；交互终端也不等于 Docker 隔离环境。产品中保留真实能力状态。
- 本次不追加 IDE 代码编辑器、任意多主任务并发写同一目录、云账户或插件市场。新的依赖、缓存、测试项目和打包产物按本机存储规则全部使用 G 盘。
