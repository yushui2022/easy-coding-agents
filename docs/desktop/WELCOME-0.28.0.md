# 0.28.0 聚焦任务的桌面布局

参考用户提供的 Pi Desktop 与 Codex 页面截图，采用居中开场、底部悬浮输入、低对比度表面和按需展开的设置。使用现有 React/Electron 工程实现可操作界面，未操作用户的应用窗口。

## 设计与实现

- `Welcome.tsx`：克制的项目问句，项目名称可点击切换文件夹；快捷任务仍只放入草稿。较长项目名自动换行。
- 生成 ECA 原创橙色折叠插画，小尺寸显示在欢迎区。原有 Logo 保留；实际资源、尺寸和完整提示词见 `desktop/src/renderer/assets/README.md`。使用内置 `image_gen`，透明 PNG 已复制进仓库，不依赖远端图片。
- 输入框底部排列验证、权限、模型与发送；项目上下文位于输入框上方。浅色使用微暖底色，深色保持表面层次，发送按钮改为中性圆形按钮。
- `TaskVerification.tsx`：验证设置按需展开，Escape 返回入口焦点，点击外部收起；保留原验证命令草稿和失败修复选项。弹层打开时遮挡原生浏览器，防止其覆盖控件。
- 任务输入随内容增高，到达上限后内部滚动。快捷键和输入法保护沿用原逻辑。

### 输入与响应测量

使用含 240 条历史消息的隐藏 Electron 窗口和本地持续流式输出，两次独立测量结果如下。输入计时从 input 捕获事件到 React 离散更新后的微任务，不能代表键盘到屏幕的物理延迟，也不代表模型服务速度。

| 指标 | 第一次 | 复核 |
| --- | ---: | ---: |
| 空闲输入事件 p95 | 5.5 ms | 9.9 ms |
| 流式输出时输入事件 p95 | 5.0 ms | 10.6 ms |
| 点击停止后的即时状态反馈 | 0.8 ms | 0.9 ms |
| 取消至清理完成 | 79.7 ms | 85.2 ms |
| 首窗出现 | 644 ms | 540 ms |

完整 E2E 中包含自动化点击和状态断言的取消计时为 2043 ms，与上表直接按钮事件计时口径不同。首窗数据不属于清空系统缓存后的冷启动测试。

性能观察器还记录到约 1 秒的长任务。追加 Chromium trace 显示该段主要为 `Commit` 的约 997.6 ms 墙钟等待，线程 CPU 约 1.3 ms；据此不能将其解释为 1 秒 JavaScript 运算，也不能宣称可见窗口不存在卡顿。可见窗口的实际呈现延迟仍未在本轮自动化中测量。原始数据与 trace 保存在 `output/performance/welcome-0-28-0*.json`。
