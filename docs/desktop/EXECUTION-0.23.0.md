# 0.23.0 执行体验与审批模式

输入框旁的审批选择器支持三档，均复用现有 Python 工具执行路径。

| 模式 | 行为 |
| --- | --- |
| 逐次确认 | 文件写入、命令、联网和外部工具按原权限路径确认 |
| 自动编辑 | 自动批准 write/edit/delete 和 LSP 应用修改；命令、联网和外部工具仍需确认 |
| 完全访问 | 明确确认后自动批准所有审批请求，包括当前等待的请求；提问仍需回答 |

审批档位属于本次打开的项目。刷新界面、切换会话或模型会保留；关闭后重新打开项目会恢复项目的 ask/accept-edits 设置。项目配置不能启用 full-access，模型也没有切换权限的工具。切回逐次确认仅影响后续审批，不撤销已启动或完成的操作。

完全访问不等于系统管理员权限。主机 shell、语言服务器和 MCP 按当前用户权限执行，可能修改项目外数据或联网；它们的效果不保证可撤销。文件工具的路径与版本检查、模式约束及现有 Docker 隔离仍生效。

## DeepSeek 响应模式

模型设置中提供快速、均衡、深入和服务默认。新连接和缺少此字段的旧 DeepSeek 桌面连接使用快速模式，已明确设置的模式保留。保存连接后须通过模型选择器用于当前项目；正在运行的请求不会被偷偷替换。

快速关闭 thinking；均衡使用 low；深入使用 high；服务默认不发送覆盖参数。只对 OpenAI Chat 协议的 deepseek 模型启用，第三方兼容地址需要支持这些参数。CLI 与项目配置默认仍为服务默认。依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。

界面展示思考字符数量，不展示思考原文。必要的 provider 回放数据保存在项目会话中并按模型及端点隔离；跨提供商、界面和摘要输入不携带原文。字符计数仅说明流活动，不用于 token 计费。

## 状态链路

新增 `live`：只返回当前运行、流式文本、阶段、待回答项、审批档位和请求耗时，不扫描历史、变更或用量。新增 `permissions.set`：参数 `mode` 为 ask、accept-edits 或 full-access。二者只通过现有私有 stdio 与限定 preload 接口暴露。

模型请求开始即显示等待状态；收到流后显示思考、工具参数生成或回答阶段，工具真正启动后再显示执行。参数还在生成时不会声称文件已写入。结构变化仍获取完整快照，文本和阶段更新按 150 ms 合并轻量刷新。
