# 个人与全局（1.3.0）

设置对话框原来只有「模型连接」一页。外观、对模型的自述、跨项目的长期指令，散落在别处或根本不存在。1.3.0 加第二页。

## 界面

左栏顶部一个分段切换：

- **模型连接**：原来的连接列表与编辑区，行为没有变化。
- **个人与全局**：三块——背景主题、个人信息、全局指令。

切换只改视图，不改数据；两页各自保存。

## 三块内容

| 区块 | 存到哪 | 生效范围 | 生效时机 |
|---|---|---|---|
| 背景主题 | `<数据目录>/theme.json`（已有机制） | 界面 | 立即 |
| 个人信息（称呼、补充说明） | `<数据目录>/profile.json`，权限 0600 | 每轮对话的系统提示词 | 下一轮 |
| 全局指令（AGENTS.md） | `<数据目录>/AGENTS.md`，权限 0600 | 每轮对话的系统提示词 | 下一轮 |

数据目录默认 `G:\Data\ECA\Desktop`（可用 `ECA_DESKTOP_DATA_HOME` 覆盖），**不写进任何项目**。

## 后端怎么拿到

主进程在启动后端之前设置两个环境变量，`RpcClient` 继承 `process.env`：

```
ECA_USER_PROFILE   = <数据目录>/profile.json
ECA_GLOBAL_AGENTS  = <数据目录>/AGENTS.md
```

`eca/usercontext.py` 的 `blocks()` 在**每次构建系统提示词**时重新读取这两个文件，所以改完立刻对下一轮生效，不需要重启后端，也不需要重启应用。

注入顺序（`agent.system_prompt()`）：项目 `AGENTS.md` → 项目 `MEMORY.md` → **用户 profile → 全局指令** → 模式与目标的附加段。项目规则在前，全局在后，两者冲突时项目表述更靠前。

### 读取的边界

- 上限：称呼 80 字、补充说明 2000 字、全局指令 20000 字；超长截断而不是报错。
- profile 的**原始文件**读取上限是 64 KB：如果按字段上限去截 JSON 本身，整个文件会解析失败、所有字段一起丢。这条是实测踩出来的。
- 符号链接、缺失文件、坏 JSON、字段类型不对，一律当「没设置」，不抛错也不阻断对话。
- 这两份内容是用户自己写的，可信级别等同项目 `AGENTS.md`：可以影响措辞和偏好，**不能**改变审批档位、不能绕过工具层的权限检查、不能在 Docker 或只读模式里放开什么。

## 主进程接口

```
personalization.get   → {name, notes, instructions}
personalization.save  → 同样的结构（已按上限截断后的值）
```

两者都在 `action()` 里本地处理，转发给后端。保存时：profile 为空则删除文件，全局指令去空白后为空也删除文件——避免留下空文件被当成"有设置"。

## 验证

- `tests/test_usercontext.py` 7 项：未配置不产生块、profile 与指令各自成块并带标签、缺失/坏 JSON/符号链接被忽略、超长截断、字段类型错误不崩、与项目 `AGENTS.md` 共存且项目在前、两者的内容都进系统提示词。
- 定向 Python 回归 116 项通过、2 跳过；TypeScript 构建、桌面单测 15 项通过。
- 隐藏窗口端到端：打开设置 → 切到「个人与全局」→ 点「深色」并读回 `theme()` → 填称呼/说明/指令 → 保存 → 校验 `profile.json` 与 `AGENTS.md` 真的落盘 → 关闭设置 → 之后**每个**模型请求的系统消息里都含称呼与全局指令。
- 未验证：macOS/Linux、非 Electron 用户手动编辑这两个文件时的即时性（每轮重读，理论上同样生效，但没有跑过）。
