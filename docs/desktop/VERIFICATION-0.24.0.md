# 0.24.0：验收失败后的修复与回归检查

这次升级直接来自 DeepSeek 实测暴露的两类问题：改动满足新增需求却破坏旧事务行为，以及模型自己编写的测试没有覆盖真正的中途失败。

## 已实现

- 桌面输入区的「验证与自动修复」可设置最多 10 条检查、0～3 次修复。填写检查后默认一次，不填检查则零次。检查命令与次数按项目保存在当前窗口的 sessionStorage，刷新保留，重新启动应用不承诺保留。
- 每轮失败、修复和复验结果进入原项目 `.eca` 会话。修改仍经过当前审批模式；拒绝、取消、超时及不确定退出不会自动修复。相同源码重复出现相同失败会停止，修复后从第一条命令重跑。
- 每次新任务重置验证状态。「所选检查通过」仅表示命令在记录的源码版本上通过，不表示所有需求或视觉效果已经合格。
- Python 文件工具修改已有公开函数、类或事务设置时，提供调用方、异常路径及中途失败的回归建议，并在压缩上下文后保留。最多检查 256K 字符的源文件，最多保留 20 个文件、每文件 8 个符号。语法失败则不推断；不覆盖 shell/MCP 写入或完整跨语言依赖分析。
- RPC 新增可选 `repair_attempts`；旧客户端省略时仍为零。`verification_progress` 是中间进度，原 `verification_suite` 仍只提供最终结果，保持 CLI 调用方兼容。

## 真实模型观察（2026-10-19）

均使用当前配置中的 `deepseek-flash`、fast 模式，凭据通过私有管道传入。没有人工编辑试验中的候选代码。以下是不同测试目的，不能相加成为首稿成功率。

| 试验 | 结果 | 用时 / 请求 |
| --- | --- | --- |
| 从初始仓库重做迁移任务 | 通过 suite 5 的原始测试和重复订单回滚检查；补充 suite 6 后仍发现迁移非原子性，不能算完整通过 | 34.75 秒 / 9 次真实请求 |
| 保留失败候选、交给桌面 RPC 复核 | DeepSeek 自行执行验收并修复了原子性错误，最终外部检查通过；运行时第一次验收即通过，不能证明运行时自动修复被触发 | 56.33 秒 / 16 次真实请求 |
| 故意注入初始“提前完成”回答，强制经过运行时失败路径 | 第一轮验收失败 → 调用真实 DeepSeek 修复 → 第二轮通过；原始和候选已有测试均保留 | 32.16 秒 / 7 次真实请求，另有 1 次合成初始回答 |
| 最终 0.24.0 从初始仓库重做迁移 | suite 6 外部验收全部通过，含重复订单回滚及迁移中途失败；无人工修复 | 33.42 秒 / 9 次真实请求 |
| 最终 0.24.0 从初始仓库做批量下单 | 原有行为、批量原子性及失败路径的外部验收全部通过；无人工修复 | 23.92 秒 / 8 次真实请求 |

第二类缺陷的复现：原候选使用 `with db:` 包裹 SQLite DDL，却没有显式开始事务。模型自己的 9 个测试全绿；外部检查在已经添加字段后拒绝写入 schema 版本号，发现失败后字段仍被保留。最终模型加入显式 BEGIN 和回滚，既通过中途失败检查，也保留原购买 API 的重复订单回滚行为。

证据位于 `output/harness-probe/upgrade-20261019-migration/`、`upgrade-20261019-repair.json`、`upgrade-20261019-repair-fault.json`，各自保留源码摘要、候选代码、会话和检查输出。首个报告是当时的 suite 5 结果；后续 suite 6 复验失败记录保存在 repair 报告的 `before` 中，没有覆盖旧报告。价格未配置，费用保持未知。

这证明有效的外部验收可以推动修复，也再次说明仅靠模型自测不足。回归建议是提示，不能保证模型完整理解所有调用关系；运行时也不会凭空知道缺少哪条业务验收条件。

最终两项复测位于 `output/harness-probe/upgrade-20261019-final/`。验收标准在运行前固定；首次运行时验收通过不等于首稿无修改。两个合成任务的小样本不能证明稳定成功率或企业级可靠性。

6 个跳过项分别为 5 个需显式启用的真实 Docker 用例、1 个缺少符号链接权限的用例；本轮不声明这些场景已验证。初次全量回归曾发现 CLI 将中间进度当最终结果的问题，已独立事件修复并复验；上下文截断测试改用相对系统提示长度的预算，继续验证完整工具轮次裁剪及预算约束。

打包程序启动到首个窗口 799 ms，重开 553 ms；挂起模型请求点击停止到已停止为 1,992 ms。任务完成后工作集为 Electron 约 477.8 MiB，加 Python 后端约 87.4 MiB。这些是有自动化调试开销的单机采样，包含操作系统缓存，不是性能承诺。

最终测试使用独立 G 盘目录与隐藏 Electron 窗口，不控制用户窗口，不改用户已有项目或凭据。机器结果见 `output/playwright/desktop-packaged-report.json`。打包程序测试使用 `win-unpacked/ECA Desktop.exe`，不等同于本机旧安装已更新；当前旧版窗口仍运行，未覆盖其程序文件。

独立、未安装 Python/Node 的 Windows 环境仍未验收。本机打包应用的 PATH 隔离测试不能替代这一项。
