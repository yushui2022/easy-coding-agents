# ECA Desktop 0.22.0：模型连接管理

## 为什么原来会显示 Qwen

0.21.x 只要发现项目 `.env` / `eca.toml` 或模型环境变量，就优先读取项目模型。桌面保存 DeepSeek 并不自动覆盖它；手动切换后，新会话还可能重新加载基础配置。0.22.0 明确区分桌面默认、项目指定连接和沿用项目配置。

## 使用方式

1. 「模型与设置」→「添加连接」，选择 DeepSeek、OpenAI、Anthropic、Ollama 或自定义兼容服务。
2. 输入连接名称、地址与密钥，点击「获取模型列表」后选择模型；服务不提供列表时可手填模型 ID。模板只预填地址与协议，不绑定一个可能过时的模型 ID。
3. 保存连接，并设为桌面默认。默认用于未指定连接的项目。
4. 输入框左下角打开模型选择器，选择「跟随桌面默认」、某个连接或「沿用项目配置」。此选择会为当前项目保存。
5. 已打开项目不因编辑连接而中断任务；保存后点击「用于当前项目」或在选择器重新选择，应用新配置。任务运行期间不能切换模型。

只配置一个 API 仍然可以正常使用。多个连接用于选择不同的主模型；此功能不会自动开启多模型派遣。CLI 的配置优先级、已有 worker profiles 和权限逻辑保持原样。

## 凭据与兼容性

- 首次打开新版时会读取旧单连接的名称、模型、端点及系统加密密文，不要求重输原密钥。下一次保存偏好时转换为 schema 2。
- 每个连接独立加密存储；渲染进程读取时只获得“已配置”状态。取消持久保存或系统加密不可用时，密钥仅存在主进程内存，重启后要求重新输入。
- 同一端点、同一协议下修改模型 ID 可复用密钥；更换端点或协议必须重新输入。模型列表和连接探针都使用同一检查逻辑。
- 本机免密钥模式仅允许 localhost / 127.0.0.1 / ::1；向兼容客户端提供无敏感意义的占位凭据，不从项目环境变量继承其他服务的密钥。
- 旧 `.env`、`eca.toml` 和项目 `.eca` 不被模型连接管理改写。桌面偏好保存项目选择，不把桌面密钥写入会话。
- 默认连接、当前使用连接和被项目指定的连接不能直接移除；先切换再删除。界面移除有二次确认。

项目默认使用桌面连接是本次针对用户反馈作出的行为变化。如果希望该项目继续读取 `.env`，在选择器明确选择「沿用项目配置」。

## 模型发现边界

只发送 GET 元数据请求，不发送项目内容或生成回答。HTTP 重定向不跟随；20 秒总超时、1 MiB 响应限制，最多展示 500 个去重 ID。分页未完整获取时标注部分结果，仍允许手填。列表不代表模型一定支持当前任务所需的工具调用能力，连接探针也不等于完整编码验收。

接口依据：[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[Anthropic 模型列表](https://platform.claude.com/docs/en/api/models/list)、[Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)。
