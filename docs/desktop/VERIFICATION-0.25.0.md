# 0.25.0 桌面响应与工作台验收

日期：2026-10-19。产品行为与审计见 [工作台设计说明](WORKBENCH-0.25.0.md)。

## 实测结论

本轮修复输入时整段历史重复渲染、流式全文重复传输与解析、折叠日志仍完整挂载的问题。结果支持“本地输入和更新开销明显下降”，不支持“所有卡顿已消失”或“模型服务生成加速”。

基准是同一台 Windows 机器上的真实 Electron，240 条合成会话消息，工具结果约 48K 字符/条，本地模型持续推送。旧版用 0.24.0 打包程序，新版用实际安装后的 0.25.0；每次创建独立项目和应用数据，不调用付费 API。运行仍受系统其他负载影响，属于单机采样。

| 指标 | 0.24.0 打包基线 | 0.25.0 安装版 |
| --- | ---: | ---: |
| 最近 50 条消息快照大小（序列化字符数） | 657,018 | 46,058 |
| 8 次快照往返中位数 | 16.9 ms | 5.8 ms |
| 空闲输入处理 P95（41 个事件） | 23.4 ms | 0.7 ms |
| 流式输出期间输入处理 P95（41 个事件） | 20.3 ms | 0.6 ms |
| 停止按钮即时反馈 | 13.6 ms | 0.6 ms |
| 本地流式任务点击派发至“已停止” | 99.4 ms | 79.4 ms |
| 启动至首个可用窗口 | 584 ms | 1,555 ms |

快照传输字符数减少约 93%；不是压缩后的网络字节数。输入时间为 input 捕获到 React 离散提交后的微任务，停止时间为 DOM 点击派发到状态变化；不含自动化点击定位开销，也不等同输入到物理显示的延迟。隐藏窗口 rAF/定时器曾出现系统节流，因此不使用早期约 1 秒的测量。启动采样新版更慢，本轮不宣称启动耗时已经优化。

两次基准均未观察到超过 50 ms 的渲染主线程长任务；这不证明所有场景均流畅。原始记录：`output/performance/baseline-024-final.json`、`installed-025.json`，脚本 `desktop/tests/performance.cjs` 与 `seed-workspace.py`。开发版的初步数据不替代这组安装版对比。

## 交互验收

- 实际模型连接配置、获取模型列表、旧配置显式切回、项目选择后明确发送、Enter / Shift+Enter / 中文输入法。
- 固定授权与窄窗口下的允许、拒绝、停止；授权时重载不重放任务；切换审批档位保留原权限规则。
- 工具调用和返回配对；折叠时没有日志 DOM；展开获取完整大结果、继续分段显示；消息变更后拒绝加载过期记录。
- 会话搜索/清空、导航折叠、超过 150 条已加载历史后的明确缺口、返回最近记录和最新滚动位置。
- 文件修改、差异、审查、撤销冲突、恢复；真实失败检查 → 修复 → 整组复验；模型错误、挂起请求取消、后端崩溃恢复与关窗清理。
- 深浅主题选定文字对比度全部达到 4.5:1；1360×860 与 900×680 逻辑窗口，窄窗口没有横向溢出，审批和停止均位于可见区域。

6 个跳过项为 5 个需显式启用的真实 Docker 用例及 1 个缺少符号链接权限的用例。第一次使用桌面构建虚拟环境跑全套测试时，因缺少旧模块的 aiofiles/pytest 而导入失败；最终改用已有完整开发环境重跑并通过，未把初次结果算作通过。CLI 打包也使用已有含 wheel 的开发环境；没有向用户环境安装新依赖。

独立、未预装开发工具的 Windows 环境仍未验收；本机 PATH 隔离不能替代干净机器测试。签名、长期多天运行和大规模真实模型成功率不在本轮完成范围。
