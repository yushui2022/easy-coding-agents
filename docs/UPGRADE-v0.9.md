# v0.9：长任务恢复与显式验收

本轮针对 StockFlow 实测暴露的上下文重复读取、输出上限中断和完成状态含糊进行升级。

## 使用

```powershell
eca --cwd G:\Projects\your-project -p "完成修改并补测试" --accept-edits --allow-shell --verify-command "python -B -m pytest -q"
```

`--allow-shell` 批准该次任务所有 Shell 命令，具有当前用户权限；只对信任的任务使用。验证命令是用户明确指定的命令，不从仓库文件或模型回复自动获取。交互模式使用 `/verify python -B -m pytest -q`，仍需逐次批准。

- `/progress` 显示最近观察、任务计划、文件修改记录和最新验证状态。模型标记的待办完成不等于实际验收。
- 最近 12 项文件操作路径/命令及 Shell 退出状态存入会话，原始结果仍在完整消息档案中。摘要不会删除该索引；每次请求在末尾附上历史观察，不改变稳定的系统提示前缀。
- Chat Completions 的 `length`、Anthropic 的 `max_tokens`、Responses 的 `max_output_tokens` 触发输出上限恢复。每次任务最多两次，仍消耗原有 `max_turns` 预算。未完成回复中的所有工具调用均不执行；提醒模型拆小文件/精确编辑，不重放此前已完成的操作。
- 普通断流、拒绝或未知不完整响应不触发上述恢复；摘要请求暂不自动恢复。已流式展示的部分文字可能留在终端，但不会作为完整助手回复保存或执行。

## 完成与验证分开

`idle` 只表示模型结束本次回复。JSONL 最后的 `status` 中增加 `verification`：

| 状态 | 含义 |
| --- | --- |
| `not_run` | 尚未显式验证 |
| `passed` | 命令退出 0、未超时，执行前后受检查的源码指纹一致 |
| `failed` | 非零退出、超时、拒绝执行或无法解析结果 |
| `no_tests` | 已识别的 pytest/unittest 输出明确报告无测试 |
| `unconfirmed_snapshot` | 命令成功，但源码指纹缺失或在执行期间变化 |
| `stale` | 历史成功后，当前受检查文件已变化 |
| `interrupted` | 检查被取消或上次进程未完成 |

单次任务：正常完成且指定检查通过返回 0；执行异常返回 1；任务未完成返回 2；模型完成但指定检查未通过返回 3；取消返回 130。没有指定验证命令时沿用原有完成退出码，不暗示验证通过。

验证记录复用普通 Shell 的审批、模式与隔离限制、持久 action 日志及取消清理。不会自动修复或重新运行验证命令；失败后查看输出，再明确要求修复与检查。

## 真实边界

这是命令证据，不是对测试覆盖率、业务正确性或生产可用性的证明。通用命令可以是构建、格式检查或测试；目前只有部分 Python 测试输出能识别“无测试”。截断输出可能缺少测试统计。指纹沿用现有项目记忆的有界源码检查（最多 2,000 文件、单文件 2 MB、合计 20 MB），忽略受保护路径和缓存；不覆盖外部依赖、数据库和服务状态。

进度索引是历史导航，不能保证模型不重复读取，也不替代源码内容和 AGENTS.md 的重新确认。本轮没有重新运行完整 StockFlow 生成，不声称已量化消除其重复压缩问题。没有新增 OS 沙箱、OAuth 或 LSP 重命名。
