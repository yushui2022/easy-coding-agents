# v0.16：上下文预算与续接摘要

本次优先完善长任务上下文，不增加模型 API 依赖，也不改变默认单 API 使用方式。

## 用法

`/context` 无需请求 API，显示当前上下文和已启用工具的 token 估算、输入上限、输出预留、安全余量和校准系数。运行时还会加入临时提示，实际请求在发送前重新检查。`/usage` 继续使用供应商返回的用量，二者含义不同。

在 `eca.toml` 的 `[agent]` 或具体 `[model_profiles.NAME]` 中配置：

```toml
context_window_tokens = 32768
max_output_tokens = 8192
context_reserve_tokens = 1024
context_chars = 100000
```

默认 32768 是应用预算，不是自动识别的模型窗口；请按实际 API 的上下文限制设置，特别是本地小模型。输入上限为窗口减去输出上限和安全余量，上例为 23552 tokens。切换档案时这些值各自使用档案配置或默认值，不继承其他模型的窗口。

## 行为

- 估算覆盖系统提示、消息、工具调用/结果、工具定义和实际发送的临时提示。按 UTF-8 对中文等非 ASCII 文本加权；它是启发式估算，不是特定模型 tokenizer。
- 自动压缩在字符或 token 输入预算达到 85% 时触发；发送前再次检查 token 预算。保留原有完整用户轮次裁剪与完整工具调用组规则。
- 主任务成功请求的实际输入用量可向上校准估算，并增加 10% 余量。Anthropic 输入包括缓存读取/创建；OpenAI 的缓存命中已包含在输入总量中，不重复相加。缺失或非法用量不参与校准。
- 校准仅保留在当前 Agent 实例中，换模型/端点/协议后重置，恢复会话时重新开始；摘要请求不影响主任务校准。
- 摘要输入保留原始需求、最新需求、旧摘要与任务计划。大段观察结果使用明确的节选标记，序列化结果仍为合法 JSON。摘要要求区分目标约束、决策、修改、检查证据、待办、不确定动作与下一步。
- 摘要失败或结果仍超预算时，旧摘要、上下文起点和完整消息历史保持不变。不会自动执行任何工具或声称验证通过。

## 边界

没有自动拉取模型元数据，也不能保证未知 tokenizer 的精确计数。模型可能遗漏摘要细节，提示词结构不等同于事实验证。目标或旧摘要本身过大时会明确停止，而不是静默删除这些内容。超大最近工具组仍可能需要缩小读取范围或另起会话。本版尚未加入供应商上下文溢出错误的自动恢复，也未完成三产品的同模型任务对照。
